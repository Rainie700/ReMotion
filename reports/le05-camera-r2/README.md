### 回放看到的（完整 0–98 秒）

- 有偵測到人的格數：50.8%。必要關節都可信（`bodyReady`）的格數：24.1%，其餘大多是走到電腦前操作、或離開畫面。
- 必要關節都可信時，平均膝角最低 **116.7°**，**沒有任何一格 ≤ 115°**。115° 是計次程式認定「起始坐姿」的門檻 `SEATED_KNEE_ANGLE_MAX_DEG`。
- 因此計次程式**從頭到尾沒有確認過起始坐姿**，一直停在待機狀態：0 次計入，0 次無法確認。
- 錄影中可以看到 4 次往下再起來，回放的最低平均膝角是：
  - 約 56 秒：118.7°
  - 約 59.5 秒：128.5°
  - 約 75 秒：130°
  - 約 77 秒：131.5°（左右差很大：L 115 / R 148）

  這幾下「應該」算幾次，本紀錄不做判斷。後兩下都不到 1 秒，回放無法分辨是坐下還是半蹲。
- 從 50 秒才開始的回放，有**一格** 114.9° 讓起始坐姿成立。之後站起來了，但坐回去只到 125.7°，湊不到「連續 3 格 ≤ 115°」，這一下沒有完成。接著走去電腦前，追蹤中斷超過 1.2 秒，被記為「無法確認」。兩次回放只差 1–2°，代表門檻剛好落在雜訊邊緣。

## 二、根因

### 已確定（依程式碼）

1. 畫面的「可以開始」只代表看得到全身，和計次是否就緒無關。這是錯誤提示，本輪已修正。
2. 計次只靠 2D 的「髖－膝－踝」角度。起始坐姿和每一下的結束，都需要平均膝角 ≤ 115°；結束時要連續 3 格。
   - F01-04 的拍攝方向設定是「正面」。
   - 同一個程式庫裡，五次坐站評估的常數明白寫著膝角「Never used to decide 'seated'」，改用髖部高度相對小腿長度判斷坐姿。
   - 訓練計次的這個設計，和正面拍攝之間有已知的衝突。
3. 結束按鈕被推到畫面外，內部狀態碼與空白分數出現在患者畫面上。本輪已修正。

### 高度可能，但尚未確定

- **0/5 的主因**：正面拍攝時，大腿朝向鏡頭，2D 膝角比實際彎曲大，坐著時大約 118–140°，所以沒有到 115°，起始坐姿與每一下的結束都無法成立。
  - 回放資料支持這個解釋。
  - 但回放用的是錄影畫素，不是原始相機輸入，所以**不能說已確認**。

### 仍缺的資料

- 原始相機畫面，或 App 內的逐格紀錄。
  - 本輪新增了 `window.__le05Trace`，只在開發模式記錄，不顯示給患者。
  - 請在同一台電腦、同一個位置，用開發模式再做一次，匯出 `JSON.stringify(window.__le05Trace)`。
- 真實拍攝角度比較：同一人分別正面、斜側面、側面坐站，看坐姿膝角的分布。需要本人同意、實際錄製。
- 使用者實際坐下的椅高與坐姿。程式本來就無法確認臀部有沒有接觸椅面。

### 本輪刻意不做的

- 沒有放寬 115° 門檻，也沒有改成用髖部高度判斷坐姿。那等於拿這支錄影調參，又沒有真實相機驗證；辨識方法要先決定，再在下一輪用真實資料驗收。
- 沒有改拍攝方向的建議。準備頁仍是「正面」。

**結論：0/5 在真實影像上的原因還沒有確認。本輪沒有「修好 0/5」。**

## 三、相機頁改了什麼

- 名稱：固定練習顯示「坐站練習」；一般 F01-04 訓練顯示動作名稱。
- 畫面只留下：
  - 相機影像；
  - 左上的狀態標籤；
  - 大字次數「0 / 5 次」；
  - 一句目前最需要的操作提示（20px 粗體）；
  - 固定在下方的「結束練習」（不在捲動區，不必捲動）。
- 移除：
  - LOST_LONG／OK 等狀態碼；
  - 平均膝角、軀幹傾斜；
  - 「AI 姿勢分數 --」與動作狀態格；
  - 重複的說明文字與「角度與分數為…」說明；
  - 頁首「AI 坐站偵測」與機器人圖示。
- 提示依計次程式的實際狀態產生（`js/ai/exercises/sitToStand/trainingGuidance.js`）：

  | 狀態標籤 | 什麼時候 | 提示（例） |
  |---|---|---|
  | 正在開啟相機 | 請求相機權限 | 正在開啟相機，請允許使用相機 |
  | 模型載入中 | 下載 MediaPipe | AI 模型載入中，請稍候 |
  | 無法開始 | 模型或相機失敗 | 畫面中顯示原因與「重新開始」 |
  | 尚未完整入鏡 | 沒有人，或缺少必要關節 | 依缺少的關節：「請讓雙腳也在畫面內，可以再退後一點」「請讓膝蓋與雙腳保持在畫面內」…（不再是「請調整位置」） |
  | 還沒確認起始坐姿 | 看得到全身，但計次程式還沒確認起始姿勢（包含站著入鏡） | 已看到全身。請先坐好，雙腳踩穩、膝蓋彎曲 |
  | 起始姿勢就緒 | 已確認起始姿勢 | 可以開始了：慢慢站起來 |
  | 練習中 | 起身、站立、坐下 | 繼續站起來，站直／站直了，慢慢坐下／慢慢坐回去，坐穩 |
  | 追蹤中斷，需要重新就緒 | 曾經就緒後失去追蹤 | 請回到畫面內，再先坐好 |
  | 已完成目標 | 達到目標次數 | 已完成 5 次，請按「結束練習」 |

  - 狀態要持續 400 ms 才切換，避免一兩格雜訊讓畫面閃動。
  - 「已計入第 N 次」與「這一下無法確認，未計入」會短暫顯示 2.2 秒。
  - 「起始坐姿」是膝角姿勢，畫面不寫成「坐在椅子上」。計入的次數也不代表動作品質合格。
- 站著入鏡再坐下時，計次程式仍照原規則記一筆 `rise_not_observed`，但畫面不再閃「這一下無法確認」，因為使用者並沒有嘗試。保存的紀錄仍會顯示「另有 1 次動作無法確認」，這屬於資料語意，需要決定，本輪沒有改。
- 狀態遮罩只在相機啟動、模型載入、失敗與完成時出現，其餘時間不再讓影像變暗。

相機頁驗收的內容：

1. 模型（真實 MediaPipe，沒有阻擋）：
   - 載入成功：「正在開啟相機 → 模型載入中 → 尚未完整入鏡」，約 12–22 秒。
   - 載入失敗（只在這一步阻擋模型網址）：顯示「無法開始」、原因與「重新開始」。網路恢復後按「重新開始」，模型就載入完成。
2. 站著入鏡且全身可見：顯示「還沒確認起始坐姿／請先坐好」，不會顯示「可以開始」，次數 0。（合成）
3. 完整一下計入 1 次；半途坐回不計入，也不延續到下一下；追蹤中斷時顯示「追蹤中斷，需要重新就緒」，回來後要重新確認起始姿勢，中斷的那一下不計入。（合成）
4. 超過 10 秒、全程有追蹤的慢動作仍計入，慢動作修正沒有退回。（合成）
5. 390、430、1280：次數、提示、結束練習都在畫面內，不必捲動，沒有橫向溢出。提示 20px、次數 44px。
6. 結束後保存實際 AI 計次 5/5；無法確認的嘗試另外記錄，不加進去；沒有自行回報；紀錄標示 `emulatorSynthetic`。
7. 一般 F01-04 訓練使用同一個相機頁，0 次時仍照原規則要求至少一次；深蹲有自己的偵測頁；五次坐站評估頁照常開啟。

**第 2–4 項（以及第 6 項的次數）只有合成測試。** 合成的 2D 關節點經過相機頁真正的處理流程，但這**不代表真實辨識已通過**。
