# 入口改版：訪客先進首頁，需要個人評估時再登入（2026-10-29，本機驗收）

這份紀錄與第 5／5 輪（`reports\ux-r5\`）分開存放。

## 範圍
沿用既有機制，沒有另寫一套流程：
- 登入／註冊（`goAuth`／`setAuthMode`／`login`／`register` 及畫面）；
- 角色規則與登入後的落點（`determinePatientLandingRoute`）；
- 「我的復健需求」問卷（可略過）；
- 首頁的下一步判斷；
- 五次坐站準備頁。

沒有改：評估演算法、推薦規則、量測使用資格、訓練量計算、權限政策與安全規則。也沒有新增訪客健康紀錄、免登入測量、預測或代操作功能。

沒有 commit、push 或部署，沒有操作正式資料或 patient00／patient01，沒有打包 ZIP。

修改前的狀態保存在 `%TEMP%\claude\…\scratchpad\pre-guest\`，包含 diff、app.js、styles.css、index.html 與 js 資料夾。

## 先查核到的現況
- 程式的起始畫面是 `splash`（產品介紹）。但登入狀態一確認是「未登入」，就會改送到登入頁，所以訪客實際上看不到介紹頁，介紹頁只在啟動時閃一下。
- 介紹頁有「插畫預留位置」「圖示」等佔位內容，也有過期說明（例如「推薦功能將於後續版本推出」「目前支援深蹲」）。
- 路由只存在記憶體（`state.route`），沒有網址路由。邀請是在 App 內輸入邀請碼，沒有深層連結或邀請網址可以保留。
- 動作介紹的資料來自隨 App 附帶的靜態檔 `js/data/rehabExercises.js`，不讀取受保護的資料，所以不需要另外拆出公開內容，也不需要放寬規則。

## 改了什麼（`app.js`、`styles.css`）

### 啟動
- `splash` 改成只顯示品牌與「正在確認登入狀態…」，等 Firebase 回報登入狀態後才決定畫面。
  - 已登入 → 個人頁。
  - 未登入 → 訪客首頁。
  - 已經開在登入／註冊畫面時保持不動。
- 確認超過 8 秒時，顯示「仍在確認登入狀態，網路可能較慢」與「重新整理」。

### 訪客首頁、訓練、數據、我的
- 未登入時，`renderDashboard` 改用訪客頁，不會顯示空白的個人儀表板。
- **首頁**依序為：
  1. ReMotion 與「登入」；
  2. 「了解身體狀態，記錄每次練習」與一句用途說明；
  3. 「開始首次評估」，旁邊註明「先查看準備說明，正式評估前需登入」；
  4. 使用流程「評估目前狀態 → 查看安排 → 練習與追蹤」，並註明「部分情況需要補充資料或由復健師確認」；
  5. 動作介紹（3 個）；
  6. 使用說明。
- **訓練**：20 個 F01 動作的「動作介紹」，內容有名稱、圖片、AI 動作辨識（依實際的偵測器判斷）與難度。
  - 不顯示組數、次數，也不寫「適合你」。
  - 單一動作頁有說明、怎麼做、注意事項，並註明「這是動作介紹，不是你的課表」。
- **數據**：說明登入後可以看哪些紀錄，並有登入與建立帳號。沒有數字，也沒有空白圖表。
- **我的**：登入、建立帳號與使用說明。
- 切換分頁時不會跳出登入。
- 舊的介紹頁內容（佔位內容與過期說明）已移除，個人化問卷頁的「插畫預留位置」也一併移除。

### 首次評估準備頁（`firstAssessmentPrep`，公開）
- 沿用五次坐站頁已核定的說明、測試前準備與安全提醒。
  - 文字抽成一份共用的 `FA5X_INTRO_TEXT`／`FA5X_PREP_STEPS_HTML`／`FA5X_SAFETY_TEXT`，兩頁顯示的內容一致。
- 「接下來」依實際步驟說明：登入、「我的復健需求」問卷（可略過）、確認鏡頭位置（這時才會要求相機權限）。見「補充修正」第 1 點。
- 未登入：「登入並繼續」「建立帳號後繼續」，並註明「登入是為了保存評估與後續追蹤紀錄」。
- 已登入：患者看到「繼續」；復健師看到說明，以及「回到首頁」。
- 這一頁不開相機，也不建立紀錄。

### 登入後接回原操作
- **意圖只保存 `{kind, at}`**，存在記憶體與這個分頁的 sessionStorage。
  - 不含密碼、token、健康資料或網址。
  - 只接受白名單裡的種類，超過 30 分鐘就作廢。
  - 回去的位置固定為 App 內的已知路由。
- **登入成功後**（`setSession`）：
  - 不是患者：依角色規則進入自己的首頁，並清除意圖。
  - 已有五次坐站紀錄或追蹤週期：進入自己的首頁與下一步，並顯示「你已經有五次坐站紀錄，以下是目前的下一步」，不會被導向新的首次評估。
  - 還沒填過「我的復健需求」問卷（可略過）：先到既有的「建立我的復健需求」，頁面會說明完成或選擇「稍後再填」後接著評估；完成或略過後，進入五次坐站準備頁。
  - 其他情況：直接進入五次坐站準備頁。相機要在那一頁按「開始評估」後才會開啟。
- **其他路徑**：
  - 登入失敗：保留意圖。
  - 取消或返回：回到原本的公開頁面，並清除意圖。
  - 重新整理：回到準備頁，意圖保留。
  - 註冊後：沿用既有的「帳號建立成功 → 前往登入」，登入後接續。
  - 登出：回到訪客首頁，清除意圖與上一個帳號的畫面暫存（草稿、選取項目、邀請訊息等）。

### 保護
- 最外層加上 render 守門：沒有登入時，只允許公開路由。
  - 公開路由：啟動、登入／註冊、訪客分頁、動作介紹、首次評估準備。
  - 其他路由不論怎麼觸發，都會回到訪客首頁。
- 正式評估、紀錄與個人資料仍需要登入，原本的權限檢查沒有改。

### 3. 尺寸驗證方式（不混稱）
- **先前的「260 寬」**：只把 viewport 設成 260 CSS px（像素比 2），是窄視窗測試。
  - 它的版面寬度與「390 寬視窗放大 150%」相同，但不是瀏覽器縮放，之前寫成「390 寬放大 150%」並不正確，已在兩份 README 更正。
- **本次新增 `scripts\domainExploreSizeCheck.mjs`（埠 5195）**，分成三種方式：
  1. **窄視窗**：viewport 260／320／390／430／1280，像素比 2。
  2. **瀏覽器縮放（等效模擬）**：Chromium 的頁面縮放會把 CSS 視窗寬改成「視窗寬 ÷ 倍率」，像素比改成「× 倍率」。
     - 390 × 844 的視窗：150% 等於 CSS 260 × 563（像素比 3），200% 等於 CSS 195 × 422（像素比 4）。
     - 無頭瀏覽器無法操作瀏覽器選單或快捷鍵縮放，所以用上述等效方式模擬，不是真的按縮放鍵。
     - 曾試過在網頁根元素套用 CSS `zoom`，但 Chromium 用這種方式不會重新排版（頁面寬變成 585，大於視窗 390），與瀏覽器縮放不同，所以不採用。
  3. **只放大文字**：390 視窗中，每個元素的字級 × 1.5，版面寬度不變，相當於系統的「放大文字」設定。
- 檢查內容：
  - 兩張卡片是否同列等高、在網格內、文字沒有被截斷；
