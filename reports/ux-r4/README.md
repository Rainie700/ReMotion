## 改了什麼

### 首頁問候

- 有本週訓練時，原本的「今天沒有復健師安排」改成中性的「今天也一起動一動吧」。
- 今天要做什麼仍由既有的主要任務卡呈現。只改了文字，沒有新增任務判斷。

### 評估結果（五次坐站）

- 完成時間仍是主角。
- 每一筆結果都標示用途：
  - 首次評估；
  - 7 日追蹤｜初次評估；
  - 再次評估；
  - 新週期基準；
  - 第一週基準；
  - 單次評估（未納入追蹤週期）。
  - 用途由 `describeFa5xPurpose` 判斷：先看已存的角色，再看這筆是否為某個追蹤週期的基準，或是否為本人第一次完成的評估。
- 測試條件改成一個「回答測試條件（約 30 秒）」入口，點開才顯示題目。
  - 不預選答案，「由誰回答」仍然必填，回報方式也沒有改。
  - 是否接受建議、是否開始週期的條件都沒有改。

### 練習結果（坐站練習）

- 主角是「AI 計次 x / 5 次（相機辨識）」。
  - 只有達到目標才顯示星星與「完成本次目標」。
  - 未達目標時，只顯示「提前結束」或「未達本次目標」與實際次數。
- 無法確認的動作會列出次數與原因（白話），不會藏起來。
- 自行回報另外一張卡片，標示「本人填寫，另外保存，沒有加入 AI 計次」。
- 只有自行回報時，主角是「自行回報（這次沒有使用相機）」。
- 主要按鈕是「查看練習紀錄」和「返回訓練」。
- 結束後立刻顯示結果。保存狀態有四種：
  - 儲存中…；
  - 已同步到雲端；
  - 僅保存在這台裝置（沒有連上雲端帳號）；
  - 尚未同步＋重試同步。
- 移出畫面：版本碼、資料欄位與重複的計次說明。只留一句「相機協助計次，無法確認是否使用手部支撐。計入的次數不代表動作品質合格。」

### 數據頁與紀錄

- 分類入口固定為「總覽｜功能評估｜訓練紀錄｜感受回報」。總覽依這三類各顯示主要數字。
- 復健師已確認的週摘要、AI 姿勢分數趨勢都保留。
- **訓練紀錄**分成三個清單：
  - **訓練**：既有的 AI 與計畫訓練，近 7 天的次數只算這一類。
  - **坐站練習**：固定練習，不計入 7 日完成天數。
  - **自行回報**：本人填寫，不加入任何 AI 計次。
  - 每一列先顯示日期、類型與主要結果，點開才看詳細內容。
  - 從這裡打開的單筆紀錄，返回時會回到訓練紀錄。
- 第 3 輪移過來的自行回報區塊重新排版：一列一筆，點開才顯示時間、說明與作廢。不再顯示內部紀錄編號。
- 新增「感受回報」頁：本人的每日回報，一般回報與週期回報分開列出。

### 評估圖表（統一）

先核對原本的三種呈現：
- 數據總覽有一條折線，相鄰兩點量測方式相同時才相連；
- 追蹤歷程有一張以週標示的圖，尚未發生的再次評估畫成「?」節點與虛線；
- 前後比較頁只有數值與文字，沒有圖。

現在只保留一張圖：`buildFa5xChart`（模型）＋ `renderFa5xChart`（畫面），放在 數據 → 功能評估，總覽只連過去。規則：
- 每個點都標示日期、秒數與用途。每週一個底色群組，標示「第 N 週」。
- 只有該週前後比較符合既有可比條件（`cmp.eligible`，已包含量測版本相容）時才畫實線。
  - 跨週不連線。
  - 不可比較的週保留兩個點，並寫出「兩次評估條件或量測方式不同，不直接比較」。
  - 既有的可比判斷不會被圖表繞過。
- 尚未發生的再次評估只畫「預計 MM/DD」的虛線框：不放數值，不畫連線，也不再出現「?」。
- 同一筆評估同時是本週再次評估和下週基準時，只畫一次，標示「再次評估／第 N 週基準」。
- 差異文字依畫面上顯示的兩個數值（各取一位小數）計算，所以看到的數字和文字一定一致。例如 12.46→12.34 顯示 12.5→12.3，文字是「少 0.2 秒」。
  - 原始毫秒差 `changeMs` 不變，所有判斷規則仍然使用它。
  - 文字只描述數值，不寫改善或退步。
- 各種狀態：
  - 沒有資料：「還沒有五次坐站評估」＋開始評估。
  - 只有一次追蹤評估：一個點＋預計日期。
  - 只有週期外的評估：列出這些評估，不畫趨勢。
  - 載入失敗：「這不代表沒有紀錄」＋重新載入。
- 全部評估紀錄（日期・用途・結果）都在圖表下方列出，點開會進入評估結果頁，返回時回到功能評估。
- 圖表比畫面寬時，只在圖表框內左右捲動，整頁不會橫向溢出。

## 固定練習「尚未同步」的調查

| 項目 | 結果 |
|---|---|
| 本專案的規則 | `firestore.rules`（2026-10-27 21:27）有 `f01FixedPracticeRecords` 區塊：本人限定，建立時檢查目標、動作與已讀，只能補填自行回報，不可刪除。本機模擬器套用這份規則時，保存都成功 |
| 使用者錄影當時的環境 | 錄影的頁首沒有「本機測試資料｜Firebase 模擬器」紅條，代表不是模擬器模式，寫入的是設定的雲端專案（`.firebaserc`：remotion-2026）。線上網站仍是 10/23 的版本，還沒有固定練習。本機沒有登入 Firebase CLI，無法讀取線上實際部署的規則，也沒有去查或修改正式資料 |
| 本機重現 | 模擬器改用「本專案規則但缺少 `f01FixedPracticeRecords` 區塊」的版本。保存被拒，畫面顯示「尚未同步到雲端＋重試同步」，App 記錄的錯誤碼是 **permission-denied**（權限規則問題，不是網路）。換回完整規則後按重試，就同步成功，也沒有產生第二筆 |
| 推論（未證實） | 最可能的原因是雲端專案部署的規則還沒有這個集合的區塊，所以寫入一律被拒。這要等有權限的人確認線上規則，或部署後再測，才能證實 |
| 部署依賴 | 要在雲端使用固定練習，需要先部署含此區塊的 `firestore.rules`（例如 `firebase deploy --only firestore:rules`）。本輪沒有部署，也**沒有**宣稱正式雲端已修好 |

調查中發現並修正的程式問題（本機可重現）：
1. **沒有雲端帳號時誤報「已同步」**：`persistRecord` 在沒有雲端使用者時直接不寫入，原本的同步判斷因此以為成功。現在顯示「僅保存在這台裝置」。
2. **失敗可能被吃掉**：保存結果原本只從共用的已完成清單判斷，若其他功能先讀走這份清單，失敗就看不到了。現在也看這筆紀錄自己的最後一次寫入結果（`storageService.getLastCloudWriteOutcome`）。
3. **錯誤碼可追查**：失敗時記錄雲端錯誤碼（`f01FixedPracticeService.syncErrorCode`），並在主控台印出 `[f01FixedPractice] cloud save of … failed: <code>`。只供開發診斷，不顯示給患者。
4. **補填自行回報時輸入被清掉**：結果頁從「儲存中」變成「已同步」時會重新繪製，正在輸入的次數會消失。現在會保留。
