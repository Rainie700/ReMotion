# ReMotion


### 第一階段：專案初始化與身分路由
此階段目標為建立前端環境，並搞定自動登入與患者/復健師的身分流轉機制。
- [x] **1-1 手機外框網頁容器：** 使用 Vite + React 建置專案，利用 Tailwind CSS 將最大寬度限制在手機尺寸（`max-w-md mx-auto`），確保網頁 RWD 看起來像原生 App。
- [ ] **1-2 啟動畫面實作：** 依簡報設計綠色調的啟動頁（Splash Screen），展示 ReMotion 官方 Logo。
- [x] **1-3 登入與身分註冊：** 實作註冊/登入介面，提供「患者（Patient）」與「復健師（Therapist）」兩種身分註冊與狀態存取。
- [ ] **1-4 雙階段自動登入與身分分流機制：**
  - [x] **【階段 A：LocalStorage 本地版】**
    - [x] 註冊時將帳密與身分（role: 'patient' 或 'therapist'）以 JSON 形式寫入本地 localStorage。
    - [x] 啟動頁（Splash）讀取時檢查快取：有紀錄（患者） $\rightarrow$ 導向患者主頁；有紀錄（復健師） $\rightarrow$ 導向復健師主頁；無紀錄 $\rightarrow$ 停留在登入頁。
  - [ ] **【階段 B：Firebase 雲端重構版】**
    - [ ] 串接 Firebase Authentication，將註冊與登入邏輯改為雲端驗證。
    - [ ] 利用 Firebase `onAuthStateChanged` 監聽登入狀態，並結合 Firestore 讀取使用者身分標籤（Role）實現自動跳轉分流。

### 第二階段：UI 介面與底部導覽列/雙端
此階段著重於 UI 刻劃，使用靜態 Mock Data 把雙端核心畫面與導覽列完整呈現。
- [x] **2-1 導覽列素材配置：** 將畫好的 Icon（home, training, data, my）切圖放入 `public/icons/`（需準備一般灰色與選取綠色兩種狀態圖片）。
- [x] **2-2 雙端底部導覽列（Bottom Navigation）：**
  - [x] 依據登入身分展示不同的切換選單（患者端：「首頁/訓練/數據/我的」；復健師端：「首頁/個案/數據/我的」）。
  - [x] 點擊時正確變更 Icon 顏色，並利用 React State 切換中間子頁面（保持底部導覽列不動）。
- [ ] **2-3 患者端畫面切版：**
  - [ ] **患者首頁：** 上方個人資訊與今日訓練計畫卡片（深蹲訓練、手臂伸展）；中間「AI 分析與建議專區（綠色小機器人圖示）」；下方「本週進度條區塊（次數、時間、熱量）」。
  - [ ] **我的數據頁：** 實作本週總覽數據卡片，並利用 `Recharts` 套件繪製訓練趨勢折線圖。
- [ ] **2-4 復健師端畫面切版：**
  - [ ] **復健師首頁：** 上方提供個案列表、今日待辦、通知三個 Tab 頁籤切換；中間為個案進度追蹤列表（如：黃小謙-進步中、陳小華-需調整）。
  - [ ] **個案詳細分析面板：** 點擊特定個案後，展示其動作正確率圓圈圖表、歷史數據，以及「派發訓練計畫」的操控按鈕。

### 第三階段：Webcam 骨架偵測與時空特徵 CNN
進入 Computer Vision 與深度學習技術層面，在瀏覽器前端即時抓取人體關節，並透過色階/光譜特徵工程進行 CNN 動作正確率動態評估。
- [ ] **3-1 前端相機串接：** 實作訓練引導畫面，成功調用並在網頁上實時顯示手機或電腦的前端鏡頭畫面。
- [ ] **3-2 骨架偵測引入：** 在 React 中引入 `MediaPipe`（或 `TensorFlow.js`），並在視訊畫面上利用 Canvas 即時繪製出人體骨架關節點。
- [ ] **3-3 動作序列特徵工程（老師推薦創新點）：**
  - [ ] **時空特徵色階化：** 將連續的關節坐標軌跡，依時間序列賦予不同色階（Color Gradient），將動態動作轉換為時空特徵軌跡圖。
  - [ ] **時頻訊號光譜化：** 將關節運動振幅視為時域訊號，透過 STFT 轉換為頻率光譜圖（Spectrogram）。
- [ ] **3-4 CNN 卷積神經網路分類器：**
  - [ ] 架設輕量化 CNN 模型（可利用 TensorFlow.js 在前端執行，或傳回後端推論），輸入上述色階圖/光譜圖。
  - [ ] 實時分類復健動作狀態（如：動作標準、速度過快、關節顫抖、角度不足），並在畫面上即時給予視覺與文字提示。

### 第四階段：後端 API 與 AI 決策 Agent
讓前端相機數據、資料庫與大語言模型（LLM）產生實時互動，落實 Agentic AI 架構。
- [ ] **4-1 訓練數據儲存 API：** 建立後端資料庫（如 Node.js + Express + MongoDB），實作使用者帳號資料、歷史訓練數據（日期、次數、時間、正確率）的儲存 API。
- [ ] **4-2 雙端資料實時互動同步：**
  - [ ] 患者做完復健 $\rightarrow$ 數據自動上傳並更新資料庫。
  - [ ] 復健師端個案面板 $\rightarrow$ 自動重載或實時更新，圓圈圖表立刻同步最新數據。
  - [ ] 復健師點擊「派發訓練計畫」 $\rightarrow$ 更新該個案在資料庫中的今日課表，患者端首頁同步變更。
- [ ] **4-3 Agentic AI 決策（LLM 串接）：**
  - [ ] 後端串接大語言模型 API（如 Gemini API）。
  - [ ] **Prompt 設計：** 將使用者的歷史復健數據、動作偏差原因與恢復狀況包裝成 Prompt 發送給 AI。
  - [ ] **建議生成：** 讓 AI 自動生成「個人化復健評估與下一步調整策略（強度、次數調整）」，回傳並顯示在患者首頁的 AI 分析區塊。

### 第五階段：遊戲化機制與細節優化
針對高齡友善與提升長輩使用動機進行細節精修。
- [ ] **5-1 遊戲化 UI 與激勵機制：**
  - [ ] 患者首頁上方加入等級（Lv.）與 XP 經驗值條，做完訓練跳出「獲得 +50 XP」特效。
  - [ ] 實作「冒險地圖」進度關卡畫面，將復健旅程圖像化。
  - [ ] 實作「成就徽章」收集牆（如：初次挑戰、連續 7 天等徽章解鎖邏輯）。
- [ ] **5-2 語音提示功能 (TTS)：** 結合 Web Speech API，在 AI 偵測到動作偏差時，用語音播放「建議蹲低一點」，方便長輩聽讀。
- [ ] **5-3 雙裝置全流程同步測試：** 使用兩台裝置進行整體流程優化與 Bug 修復，確保從患者復健到復健師動態調整的閉環順暢無阻。

## 技術架構與模組
* **Frontend:** React.js, Tailwind CSS, Vite, Recharts
* **Computer Vision:** MediaPipe / TensorFlow.js (MoveNet)
* **AI Engine:** Large Language Model (Gemini API)
* **Backend:** Node.js, Express, RESTful APIs
* **Database:** MongoDB / Firebase
