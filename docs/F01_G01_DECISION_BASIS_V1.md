# F01 G01 決策依據 v1：來源 → 可支持決策 → 程式修改

狀態：查證與案例對照，2026-10-27。第一～五節是實作前的查證；第六節是之後實作的 G01 下一階段決策修正與驗收（決策邏輯驗證，不是臨床準確率）。
本文件沒有任何專業人員確認。文中「工程政策」是本專案的產品規則，不是臨床結論。

## 〇、簡答

1. **有來源支持的決策**
   - **首次 G01 不依五次坐站秒數選動作**：Otago 依觀察到的動作表現決定起始等級；Yin 2023 沒有談選擇動作。現行引擎不讀秒數（R11），與此一致。
   - **不用手的坐姿起立只給回報「沒有用手、沒有協助」的人**：與 NHS、Otago 的不用手版本一致。這是條件篩選 v1，已實作。
   - **前後差距在參考值內時，不當成有變化**：這是 MDC 的直接意義，但只在同一測量方式下成立。
   - **回報新的或加重的不適時，不進階，並交由人確認**：Otago 寫明要在無痛範圍內練習，疼痛不退時停止並就醫。
2. **超出來源的決策**
   - D5 只憑五次坐站的時間變化就判「進階」（R005）或「調整」（R010）。
   - 把 3.12 秒用在另一種量測與族群上。來源是由治療師計時、手交叉胸前、41 公分椅子的照護需求者肌少症組；App 是相機量測、居家椅子、可能用手。
   - 完全不看已收集的測驗條件回報（用手、協助、是否同一張椅子）。
3. **下一輪最值得改的一項**：再評估的「測驗條件可比性」檢查。
   - 前後任一次回報用手、有人協助或換了椅子時，時間差不再拿 3.12 秒分類，也不能單憑時間判進階或調整。
   - 修改前：N11、N12 判「進階」（R005）。
   - 修改後：判「維持」，並寫明「前後測驗條件不同或未確認，時間差不作判定依據」；未確認的情況另提示補回報。
4. **驗證方式與證明不了的事**
   - 驗證：用本文件第四節的 12 個合成案例，比較修改前後；條件相同的案例（N01–N10）輸出必須不變。
   - 證明不了：這不能證明推薦更準確，也不能證明 3.12 秒適用於 App 的相機量測。App 自己的量測誤差沒有資料。

## 三、來源 → 可支持決策 → 程式修改

只列最有價值的三項。每項分成「值得顯示給人看」和「足以自動改變結果」兩部分。

### 第 1 項（最優先）：再評估的測驗條件可比性

| 欄位 | 內容 |
|---|---|
| 來源 | S1 Methods 2.4（雙手交叉胸前、41 公分椅、同一位治療師）；S2 Appendix 1 p. 25（無扶手硬椅、雙臂交叉） |
| 對象與情境 | S1 的 MDC 只在同一套測法下成立。App 的前後兩次可能一次用手、一次不用手，也可能換了椅子 |
| 直接支持 | 測法不同的兩次時間，沒有依據拿 3.12 秒判斷「超過誤差的真實變化」 |
| 不能推出 | 不能推出測法相同時 3.12 秒就適用於 App 的相機量測，也不能推出條件不同就代表使用者退步 |
| 需要的輸入 | 基線與再評估的 `conditionReports`（`armsUsed`、`physicalAssistance`、`sameChairAsBaseline`）：**已有**（再評估會問是否同一張椅子） |
| 建議的實際決策 | 在 `buildTrackingComparison` 或 D5 輸入加一個「條件可比」檢查：<br>- 任一次回報用手或有人協助，或再評估回報不是同一張椅子：時間差不分類，不走時間矩陣；有訓練暴露時判「維持」，沒有暴露時「不自動判定」；畫面仍顯示兩次時間。<br>- 任一項回報不確定或沒有回報：處理相同，另提示用既有表單補回報。 |
| 工程政策 | 「不確定或未回報也視為不可比」以及「不可比時改判維持」是工程政策。「測法不同不能套 MDC」是來源直接推論 |
| 顯示或自動 | 兩次時間與條件差異：**顯示**。不以時間判進階或調整：**自動**（只是不做改變，不換動作） |

### 第 2 項：時間差不單獨構成「進階」或「調整」

| 欄位 | 內容 |
|---|---|
| 來源 | S2 pp. 14–16、S3 pp. 5、8：進階依「動作本身的表現與反應」（2 組 10 下、從扶到不扶），由指導員或治療師決定，功能評估每 3 個月一次。S1：MDC 只代表量測上的真實變化，沒有談訓練決策 |
| 直接支持 | 沒有任何已查來源支持「7 日內五次坐站快 ≥3.12 秒且 6/6 天，就進階」，或「慢 ≥3.12 秒就調整」 |
| 不能推出 | 不能推出時間變化沒有意義（它仍是量測上的變化），也不能推出應該退階 |
| 需要的輸入 | 時間差、完成天數：已有 |
| 建議的實際決策 | G01 下一週的 R005 改為「維持」，理由寫明「時間較快且超過參考值，但本版不以時間單獨判定進階」。R010 改為「維持並請確認量測條件與近期狀態」，不再說「本週功能變化需要調整」。<br>G01 的動作本來就不會變（沒有 G01 轉換），**改變的是判定標籤、理由文字，以及之後 LLM 草稿收到的判定** |
| 工程政策 | 「改判維持」是工程政策。「時間不是來源的進階依據」是來源直接 |
| 顯示或自動 | 時間差與參考值的比較結果：**顯示**。進階或調整的自動判定：**移除** |

### 第 3 項：每日吃力與不適回報只用來「暫停進階」並顯示

| 欄位 | 內容 |
|---|---|
| 來源 | S2 p. 15「中等強度、不應過度疲累」、p. 16 無痛範圍與停止條件；S3 p. 8「依病人對運動的反應」進階 |
| 直接支持 | 回報很吃力或不舒服時，不應往上加難度，並應讓專業人員知道 |
| 不能推出 | 不能推出應該自動退階、換成哪個動作、減幾組；也不能把「很吃力」當成疼痛或傷害 |
| 需要的輸入 | 每日 `effort`、`discomfort`、未完成原因：**已有**，但 D5 不讀 |
| 建議的實際決策 | 週期內有「很吃力」、「有不舒服」或未完成原因為「太吃力」或「不舒服」時，D5 不得給「進階」，並在提案中列出這些回報給使用者與復健師看。不自動調整動作 |
| 工程政策 | 觸發條件（例如「任一天」或「幾天以上」）沒有來源，屬於工程政策，需另行訂定並標示 |
| 顯示或自動 | 回報內容：**顯示**。暫停進階：**自動**。退階或換動作：**不做** |

其他判斷：**首次 G01 不需要新增依秒數選動作的規則。** S2、S3 依觀察到的動作表現選等級（扶或不扶、幾下）；App 只有「不用手」一個版本，而且辨識看不到手，所以目前沒有可自動選擇的「動作版本」。要支援 Otago A／B 那種扶手版本，需要先有該版本與能確認手部支撐的辨識，這屬於下一輪「動作形式與辨識」的範圍。

## 五、查證缺口與可保留範圍

- **缺口 1**：App 相機量測五次坐站的前後測誤差（App 自己的 MDC）沒有任何資料。3.12 秒是另一種量測方式（治療師計時）的數值。
- **缺口 2**：沒有找到適用於「居家、無專業人員到府、7 日週期」的坐站訓練進退階依據。Otago 是完整方案，但需要治療師處方與回訪，以 3 個月為評估間隔，對象是 80 歲以上、曾跌倒者。
- **缺口 3**：「吃力程度」在幾天以上要暫停進階，沒有來源。
- **缺口 4**：Alexander、Hirono、Pankheaw 三篇只讀過摘要；Otago 2007 手冊的 Table 4 是圖片，坐站分級改以 2023 年 UNC 版本 p. 30 核對。
- **可保留的範圍**：
  - 首次 G01 現行做法：不讀秒數、條件篩選 v1。
