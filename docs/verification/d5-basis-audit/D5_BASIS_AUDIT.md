## 3. 「判定進階」與「確實套用進階」

| 層次 | 欄位 | 意思 |
|---|---|---|
| 規則判定 | `d5.matrixDecision = "progress"`，`decisionRuleId = "R005"` | 符合 R005 |
| 實際決定 | `d5.decision`（即 `selection.effectiveDecision`） | 有可用的進階轉換時是 `progress`；沒有時是 `maintain` |
| 實際安排 | `resolveD5Arrangement().actualLabel` | 「進階」或「維持（沒有套用進階）」 |
| 訓練量 | `items[].dose` | **兩種情況都不會增加**。換動作時採用新動作的預設量。 |

即使「確實套用進階」，也只是把 1 個動作換成轉換表中的下一個動作，然後等病人接受。

## 4. 模擬：從 Phase C 初次推薦出發，「進階」實際能套用多少

做法：用既有純函式以唯讀方式在本機計算。條件如下：
- 5 個目標 × 3 個時間選項（10/15/20 分鐘，對應 1/2/3 個動作）× 32 種 L01～L05 組合
- D5 時的限制與 Phase C 相同
- 一律假設判定為進階
- 候選資料與 App 相同，已移除 F01-19
- 模擬腳本放在 scratchpad，不屬於專案

**結果：480 份初次推薦中，只有 32 份（6.7%）會真的換動作，而且全部是 G04 的 F01-09 坐姿抬膝 → F01-11 站姿髖屈曲。**

沒有限制時，各目標的情形：

| 目標 | 初次動作（10／15／20 分鐘） | 判定進階後 |
|---|---|---|
| G01 起身更順 | F01-04／+F01-01／+F01-10 | 全部維持：G01 沒有 Confirmed 的進階轉換（Excel 註明 G01 不自動把 F01-04 換掉） |
| G02 整體下肢力量 | F01-01／+F01-02／+F01-04 | **全部維持**：F01-01 沒有進階轉換；F01-04→02 與 F01-02→01 的目標動作都已在清單中，因為不能重複而被略過 |
| G03 膝部 | F01-02／+F01-03／+F01-05 | 全部維持：G03 只有同目標替換 |
| G04 髖部與骨盆 | F01-09／+F01-10／+F01-11 | 10、15 分鐘：F01-09→F01-11 一次，之後沒有下一階；20 分鐘：F01-11 已在清單中，所以維持 |
| G05 足踝 | F01-17／+F01-18／+F01-20 | **全部維持**：唯一標為 Evidence 的 F01-17→F01-19，因為 F01-19 在 App 中被排除 |

限制：
- 復健師確認過的安排可能包含其他動作組合，例如 G02 只有 F01-04，這時進階的可套用範圍會不同。上表只代表「從系統初次推薦開始」的情形。
- 兩次訓練量相同：F01-09 與 F01-11 的預設量都是 3 組 × 10 下。所以即使套用進階，訓練量也沒有變化。

## 6. 建議優先處理的一個缺口：G1「不自動判定」時，復健師無法安排下一週

**為什麼是這一項**
- 「不自動判定」很容易出現：
  - 任何一個沒有完整訓練日的週期，只要變化不是「較快」（R006、R009）；
  - 兩次評估量測版本不同的週期，例如 1.1 升級到 1.2 前後，必定是 R001；
  - 新版本計量待定的週期。
- 這些情況下，系統**完全沒有**往下一週的路：連有關聯的復健師也被程式擋住。
- 其他缺口有替代做法或風險較低：進階永遠要人確認，而且不會增加訓練量。
