### 0.5 其他名詞與限制

- 小腿長：膝到踝的 2D 距離，取雙腿平均，在建立坐姿基準時取中位數（`assessmentSession.js:221-226`）。
- d（髖位移）=（坐姿基準的髖 y − 目前的髖 y）÷ 基準小腿長（`assessmentSession.js:109-111`）。
- 幀：一次鏡頭推論，最短間隔 66 ms（`js/ai/squatConstants.js:80`）。實際間隔視裝置而定。
- 文中「可能誤算／漏算」都是從程式推論出來的，**沒有經過真人或實拍驗證**。合成資料測試只能證明程式照設計執行，不是臨床依據。

## 1. 站完整（完全站直）

**人的動作要求**
- 【PDF 已核實】口令要求「務必完全站起」（p1）；起始時雙手交叉抱胸（p1）；不用手（p1、p2 Q4）。PDF 沒有量化「完全站起」。
- 【Excel 整理】要「起立到完全站直」（B13、B31）；雙手交叉、不可推撐（B11-4、B11-8）。

**現行程式的判斷**
- 計時中，站立幀必須同時符合兩個條件（`assessmentSession.js:307-308`）：
  - d ≥ **0.7 小腿長**
  - 膝角 ≥ **150°**。只有量得到膝角時才檢查這一條。
- 連續 **3 幀**符合，才確認站直；站直的時間點記在第 1 個確認幀（`assessmentSession.js:318-321, 339-348`）。
- 膝角是兩腿「髖-膝-踝」2D 夾角的平均值，兩腿都要量得到（`poseMath.js:5-7`；`assessmentFeatures.js:116, 123`）。
- **不檢查手**：必要關鍵點不含手腕（`assessmentConstants.js:51-56`），程式中沒有任何手部判斷。

**依據與分類**

| 內容 | 分類 |
|---|---|
| 要完全站起 | 【PDF 已核實】（p1） |
| 0.7、150°、3 幀 | 【工程候選】（`assessmentConstants.js:78-79, 83`）。PDF 沒有，Excel 也標為 No Evidence Found（B36）；Excel B31 並且反對套用其他動作的角度標準 |
| 用手時記 0 分或中止測試 | 【PDF 已核實】（p1、p2 Q4）。**程式沒有實作** |

**可能誤算或漏算**
- **誤算**（未完全站起卻被接受）：見第 6.1 節。
- **誤算**（用手推撐也被接受）：PDF 規定，第 1 次就要用手時應中止測試，用手完成時應記 0 分或「unable」；程式卻會照常計次並給出時間。
- **漏算**（真的站直卻被拒絕）：
  - 站直的時間不到 3 幀（約 0.2 秒以上，依裝置而定）。
  - 側面拍攝時，膝蓋伸不直的人一直達不到 150°。
- 0.7 小腿長是否等於完全站起，取決於體型、椅高和拍攝角度，**未經實測**。

**後續人工對照應標記**
- 每一次起立的最高點：完全站起或沒有完全站起；膝、髖是否伸直。
- 是否用手推撐（推椅面、膝蓋或其他物品）。
- 程式的判定（站直或拒絕），以及當時的 d、膝角、膝角是否可用：逐幀紀錄中的 `diag.standingNow`、`kneeOk`、`kneeAngleAvailable`。
- 拍攝角度與椅高。

## 2. 坐回來（完整坐回）

**人的動作要求**
- 【PDF 已核實】
  - 停止計時的條件是「身體碰到椅子」（p1）。
  - 每次之間盡量不讓背碰到椅背，不要用腿後側抵住椅子（p1、p3 Q7）。
  - 起始時背靠椅背（p1）。
  - PDF 沒有逐次定義「坐回」。
- 【Excel 整理】每一次都要坐下到「臀部完全碰椅面」（B13）。

**現行程式的判斷**
- 坐回幀：d ≤ **0.12 小腿長**（`assessmentSession.js:309`），連續 **3 幀**才確認，時間點記在第 1 個確認幀（`assessmentSession.js:322-325, 365-371`）。
- 開始下坐：d < 0.7 − **0.1**（`assessmentSession.js:358`）。
- 坐姿基準：坐著不動 **1.5 秒**、髖部晃動 ≤ **0.06 小腿長**，取中位數（`assessmentSession.js:203-233`）。
- 程式不判斷身體是否真的碰到椅子；也不判斷背有沒有碰到椅背，或腿後側有沒有抵住椅子。
- App 的事前說明沒有提到「起始背靠椅背」，也沒有提到「每次之間不碰椅背」（`app.js:6461-6473, 6767`）。

**依據與分類**

| 內容 | 分類 |
|---|---|
| 「碰到椅子」作為停止點 | 【PDF 已核實】（p1） |
| Excel 寫成「臀部碰觸椅面」 | 【Excel 整理】，與 PDF 的用詞不同（見第 0.4 節） |
| 0.12、0.1、3 幀、1.5 秒、0.06 | 【工程候選】。PDF 沒有，Excel B30 也寫明是工程轉譯 |

**可能誤算或漏算**
- **誤算**：
  - 臀部懸在椅子上方，但在 0.12 小腿長以內，被算成坐回。
  - 停止時間因此可能偏早。
- **漏算／時間偏差**（PDF 補充後才看出的新風險）：
  - 依 PDF，起始時要背靠椅背，每次之間卻要避免碰椅背。所以坐姿基準是在「背靠椅背」時建立的，之後每次坐下的位置可能不同（例如坐得比較前面），髖部的 2D 高度也可能跟基準不一樣。
  - 如果差距超過 0.12，就一直無法確認坐回；如果差距方向相反，則可能提早確認坐回。
  - 這些都是推論，**未經實測**。
- 坐下時間短於 3 幀就立刻再起身：如果下坐已超過一半，判為「未完整坐回」並拒絕；不到一半則當成晃動。

**後續人工對照應標記**
- 每一次：身體碰到椅子的時間；碰到之前有沒有懸空停頓。
- 背有沒有碰到椅背；腿後側有沒有抵住椅子。
- 坐的位置是否和建立基準時不同。
- 程式記錄的 `reps[].seatedMs` 與人工標記時間的差距。

## 3. 完成一次與拒絕計次

**人的動作要求**
- 【PDF 已核實】
  - 「坐→站→坐」連續 5 次（p1）。
  - 只做 1 次正式測試（p1）。
  - 沒有完成 5 次，記為 0 秒並註明原因（p1、p3 Q5）。
  - 需要他人協助，記為 0（p3 Q6）。
  - PDF **沒有寫**單次動作不完整時該怎麼處理。
- 【Excel 整理】由完全坐姿到完全站直、再回到完全坐姿算一次（B31）；用手推撐、需要他人協助或無法完成，都視為失敗（B13）。

**現行程式的判斷**
- 一次的流程（`assessmentSession.js:328-404`）：
  1. 坐姿
  2. d ≥ **0.15** 時進入「起身中」
  3. 站立條件連續 3 幀，進入「已站直」
  4. d < 0.6 時進入「坐下中」
  5. 坐回條件連續 3 幀，**計一次**
- **未完全站直**：起身後還沒確認站直，就連續 3 幀坐回。這一次不計，測試繼續（`assessmentSession.js:349-353`）。
- **未完整坐回**：下坐已達一半（d ≤ **0.41**），卻在確認坐回之前又站起來。這一次不計，回到「已站直」狀態（`assessmentSession.js:385-397`）。
- 被拒絕的動作不會中止測試，但使用者必須多做一次補足。計滿 5 次即完成（`assessmentSession.js:386`）。
- 結束結果：
  - 計時超過 60 秒、使用者取消：**未完成**（incomplete）。
  - 追蹤中斷、畫面改變、起始姿勢不是坐姿：**無效**（invalid）。
  - 上述狀態都**不提供總時間**（`totalDurationMs: null`，`assessmentSession.js:153`），並記錄原因。

**依據與分類**

| 內容 | 分類 |
|---|---|
| 5 次、只做 1 次正式測試 | 【PDF 已核實】 |
| 沒完成 5 次、需要用手或需要協助時記為 0／unable，並註明原因 | 【PDF 已核實】（p1、p2 Q4、p3 Q5–Q6）。PDF 的「0／unable」是**受測者依標準程序無法完成**的結果。程式的狀態**不能等同**於它（見下方說明） |
| 拒絕後繼續做、多做一次補足 | 【依據待確認】。PDF 與 Excel 都沒寫 |
| 0.15、0.41（一半規則） | 【工程候選】 |
| 60 秒上限 | 【工程候選】。PDF 沒有時間上限；Excel 只寫「不可中途暫停過久」 |

**程式狀態與 PDF「無法完成」的對應（2026-10-21 更正）**

上一版寫成「程式不給時間，與 PDF 方向一致」，這個說法不正確，已更正如下：

| 程式狀態 | 實際意思 | 能否等同 PDF「0／unable」 |
|---|---|---|
| **量測無效** invalid（追蹤中斷、畫面改變、起始時不是坐姿） | **系統沒有量到**，跟受測者能不能完成無關 | **不能**。這是量測失敗，不是受測者的表現 |
| **未完成** incomplete（逾時 60 秒、使用者按結束） | 沒做滿 5 次，但**原因不明**：可能做不到，也可能是中途被打斷、手機出問題，或使用者自行停止 | **不能直接等同**。只有確認是「做不到」時才符合 PDF p3 Q5；60 秒逾時算不算做不到，PDF 沒寫 |
| **完成** completed，但有用手或他人協助 | 程式偵測不到，照樣給完成時間 | 依 PDF p1、p2 Q4、p3 Q6，**應該是 unable**，程式卻判為完成。這是反方向的落差 |

所以，程式目前**沒有任何一種狀態**能正確對應 PDF 的「依標準程序無法完成」。

**可能誤算或漏算**
- 被拒絕的那一次，耗時仍算在總時間內，而且要多做一次，所以總時間會變長。臨床施測者遇到同樣情況可能會重測，或依 PDF 判為無法完成，兩種結果不能直接比較。
- 第 1、2 節所說的誤收與誤拒，會讓總時間偏短或偏長。

**後續人工對照應標記**
- 每一次動作的類別：完整、未站起、未坐回、用手、他人協助、背碰椅背、腿後側抵住椅子、中途停頓。
- 程式的 `reps`、`rejectedAttempts`（原因與發生時間 `atMs`）。
- 依 PDF，人工判定應該是「有效時間」「0 分／unable（並寫原因）」或「需要重測」，再和程式的結果狀態對照。

## 4. 計時開始與結束

**人的動作要求**
- 【PDF 已核實】
  - 計時從施測者說「Go」時開始；在第 5 次之後，身體碰到椅子時停止（p1）。
  - 記到秒的小數點後一位（p1）。
- 【Excel 整理】
  - 說「預備、開始（Ready, Set, Go）」後啟動碼表（B11-5、B11-7）。
  - 第 5 次坐下、臀部碰觸椅面時停止（B13）。
  - Excel 的 CV 轉譯建議用「髖部明顯上移」作為開始（B30）。

**現行程式的判斷**
- **開始**：倒數 3-2-1（每步 1 秒）之後的第一個推論幀，就是 `startCueAt`，計時從這裡開始（`assessmentSession.js:251-262`）。
  - 同一幀會送出提示，App 才開始播放語音「開始」（`app.js:7056-7061`）。
  - 計時定義為 `start_cue_to_fifth_seated`（`assessmentConstants.js:43-48`）。
- **偷跑**：倒數期間 d ≥ 0.15，就重新準備（`assessmentSession.js:241-246`）。
- **起始姿勢不是坐姿**：第一次起身前 d ≤ −0.25，判為無效（`assessmentSession.js:302-305`）。
- **結束**：總時間 = 第 5 次坐回的第 1 個確認幀 − `startCueAt`（`assessmentSession.js:153, 371, 386`）。
- **另外記錄**：動作開始時間 `movementOnsetMs`（`assessmentSession.js:301`）。
- **上限**：60 秒（`assessmentSession.js:275-278`）。
- **顯示**：時間以秒為單位，取到小數點後一位（`app.js:6532` 的 `fmtFa5xSec`、`app.js:6857-6860` 的 `fmtFa5xClock`）。儲存的值是毫秒。我沒有逐一檢查每個顯示路徑是否都使用這兩個函式。

**與來源的比對**
- **計時起訖對應的事件**：程式「說開始時起算、第 5 次坐回時停止」，和【PDF 已核實】的「說 Go 時開始、第 5 次後身體碰到椅子時停止」**對應的是同一組事件**。
  - 但兩邊取得起訖時間點的方式不同（見下方操作差異），所以**不能說計時一致**。
  - 程式算出的時間和人工碼表時間有多接近，**尚未驗證**。
  - （2026-10-21 更正：上一版寫成「定義一致」，容易被讀成計時相同。）
- **刻意不同**：程式沒有採用 Excel B30 的 CV 轉譯建議（用動作開始計時），只把動作開始時間記成 `movementOnsetMs`。這一點和 PDF 一致。
- **操作層面的差異**（定義相同，但量法不同）：
  1. 程式從「發出語音那一幀」起算，不是人聽到的瞬間。語音延遲沒有量過。
  2. 程式停在「髖部回到基準附近的第一幀」，不是身體碰到椅子的瞬間。
  3. 口令是 3-2-1 倒數加「開始」。PDF 只說「Go」，沒有倒數，也沒有「預備」。這屬於【工程候選】的 UX 設計。
  4. 開始和結束各有至少 66 ms 的取樣誤差。
- **時間精度**：顯示到小數點後一位，與 PDF 一致。
- **60 秒上限**：PDF 沒有，屬於【工程候選】。
- **偷跑**：PDF 沒有寫，處理方式屬於【依據待確認】。

**可能誤算或漏算**
- 語音延遲加上人的反應時間，可能讓總時間偏長。
- 停止點可能早於身體真正碰到椅子，讓總時間偏短。
- 第 5 次坐回剛好在追蹤短暫中斷時發生，停止時間最多可能延後約 1.2 秒（見第 5 節）。

**後續人工對照應標記**
- 「開始」語音實際出現的時間、第 5 次身體碰到椅子的時間、第一次離開椅子的時間。
- 人工碼表時間、影片標記時間、程式的 `totalDurationMs`，三者並列，並記錄差異的方向與大小。

## 5. 追蹤不足、遮擋等無法可靠判斷的情況

**人的動作要求**
- 【PDF 已核實】PDF 是人工施測的規範，**沒有這一項**。
- 【Excel 整理】B37 寫到的是一般電腦視覺做法，例如「暫停計時並提示調整鏡頭」，並標為工程設計，沒有專屬依據。

**現行程式的判斷**
- **追蹤到**的條件：雙側肩、髖、膝、踝共 8 個點，可見度都 ≥ **0.55**，而且影像尺寸有效（`assessmentFeatures.js:38-47, 86-109`）。可見度是模型輸出的信心值，不保證那個點真的沒有被遮住。
- **準備階段**：
  - 沒追蹤到時，回到調整位置的步驟。
  - 取景檢查：離邊緣 0.02、頭頂空間 1.0 小腿長、身高佔畫面 0.3（`assessmentFeatures.js:155-165`）。
- **計時中**：
  - 中斷不到 **1.2 秒**：容忍，計時不暫停，中斷期間的幀不參與判定（`assessmentSession.js:284-292`）。
  - 中斷達 1.2 秒以上：判為無效。
  - 畫面比例改變：判為無效（`assessmentSession.js:279-282`）。

**依據與分類**

| 內容 | 分類 |
|---|---|
| 所有數值：0.55、1.2 秒、0.02、0.3、1.0 | 【工程候選】。PDF 與 Excel 都沒有 |
| 「計時不暫停、中斷超過時限就判無效」 | 和 Excel B37 舉例的「暫停計時」不同，屬於【依據待確認】。B37 本身也只是工程建議 |

**可能誤算或漏算**
- **確認幀可能跨過中斷**：中斷期間不會重設確認計數，所以「連續 3 幀」可能是中斷前後的幀拼起來的。這是推論，未經實拍驗證。
- **漏算**：起身到站直的過程剛好全在中斷期間，恢復時人已經在下坐，結果被判為未完全站直。
- **時間偏移**：第 5 次坐回剛好在中斷期間，停止時間延後。
- **假的追蹤**：被遮住的點，模型可能仍然給出 0.55 以上的猜測位置，程式會照常使用。

**後續人工對照應標記**
- 遮擋或離開畫面的起訖時間，以及被遮住的部位。
- 程式在這段期間的 `tracking_gap` 與確認計數。
- 中斷前後是否剛好發生站直或坐回的確認。
- 可見度很高、但目視明顯錯位的片段。

## 6. 特別核對

### 6.1 膝角量不到時只看髖部位移，可能接受哪些未完整站起？

**這個分支在計時中幾乎不會發生**
- 計時中，判定前必須先「追蹤到」，也就是雙側髖、膝、踝的可見度都 ≥ 0.55（`assessmentSession.js:284`）。
- 計算膝角需要的就是這些點，而且用同一個門檻（`assessmentFeatures.js:87, 123`、`poseMath.js:4-7`）。
- 所以在計時中，膝角量不到只會發生在三點中有兩點完全重合的情況（`js/ai/poseMath.js:15`）。

**真正的風險在拍攝角度**
- App 指示「手機固定在前方」（`app.js:6462`）。
- 測試程式假設：正面拍攝時，坐著的 2D 膝角也約 170°（`tests/fiveTimesSitToStandAssessment.test.js:25, 39`）。這是合成資料的假設，**未經實測**。
- 如果這個假設成立，膝角條件幾乎都會通過，「站直」實際上主要只看「髖部上升 ≥ 0.7 小腿長」。

**可能被接受的未完整站起**（都是推論）
1. 髖、膝仍然彎曲的半站，只要髖部上升已經達到 0.7 小腿長並維持 3 幀。
2. 身體往鏡頭靠近、相機角度改變、手機移動，造成畫面中髖部的位置改變。
3. 建立基準時坐得比較低。依 PDF，起始時背靠椅背；如果之後每次都坐得比較前面、比較高，半站就更容易達到門檻。
4. 用手推撐站起，因為程式本來就不檢查手。依 PDF p1、p2 Q4，這種情況應記為 0 或「unable」。

**反向風險**
- 側面拍攝時，150° 可能讓膝蓋伸不直的人一直被拒絕。
- PDF 只要求「務必完全站起」，沒有提供任何角度或高度。

### 6.2 「口令開始，到第五次坐回停止」是否與引用來源一致？

- **起訖事件：對應相同；計時本身：不一致，也未驗證。**（2026-10-21 更正：上一版寫成「定義：已核實一致」）
  - PDF p1：「Time starts when the tester says "Go."」、「Time stops when the patient's body touches the chair following the fifth repetition.」
  - 程式的 `start_cue_to_fifth_seated` 指向同一組起訖事件，但時間點的取法不同：
    - 開始：PDF 是施測者說出「Go」的瞬間；程式是手機發出語音的那一幀。
    - 停止：PDF 是身體碰到椅子的瞬間；程式是髖部回到起始高度附近的第一幀。
  - 程式時間和人工計時的差距**沒有量過**。在完成人工對照之前，只能說「起訖事件對應相同」，不能說「計時一致」。
- **Excel 與 PDF 的差異**（並列，不判定誰對）：
  - Excel 寫「預備、開始（Ready, Set, Go）」，PDF 只有「Go」。
  - Excel 寫「臀部碰觸椅面」，PDF 寫「身體碰到椅子」。
  - Excel 引用的 SRALab 網頁與 Medbridge 原文都**尚未核實**。
- **操作差異（仍待確認）**：
  - 從語音發出的那一幀起算，而不是說出「Go」的瞬間。
  - 停在髖部回到基準附近，而不是身體碰到椅子。
  - 使用 3-2-1 倒數。
  - 這些差異是否影響和文獻常模比較，需要專業確認，也需要人工對照量出差異大小。

### 6.3 數值有沒有直接依據？

**結論：PDF 和 Excel 都沒有支持任何一個判定數值，全部仍標為待驗證。**

- **每一次動作**：完整、未站起、未坐回、用手、他人協助、背碰椅背、腿後側抵住椅子、中途停頓。
- **整體判定**：依 PDF 判為「有效時間（到小數點後一位）」或「0／unable（並寫原因）」；必要時另外記錄臨床人員認為的較少次數時間，這不算一次正式測試（p1、p3 Q5）。
- **遮擋**：起訖時間、被遮住的部位、目視錯位的片段。
- **對照程式**：
  - 結果欄位：`status`、`completedReps`、`totalDurationMs`、`reps[]`、`rejectedAttempts[]`、`movementOnsetMs`、`trackingLossCount`
  - 開發模式的逐幀紀錄
- 這些資料用來校正門檻。在完成校正之前，不能宣稱準確度。

## 9. 白話摘要

### 已確認（PDF 原文已核實）

- 計時從說「Go（開始）」時起算，到第 5 次之後身體碰到椅子時停止。**程式對應的是同一組起訖事件，但時間點的取法不同。程式時間是否與人工計時一致，尚未驗證。**
- 要連續做 5 次、只做 1 次正式測試、時間記到小數點後一位。**程式在這三點上一致。**
- 要完全站起、雙手交叉抱胸。用手才站得起來、需要別人扶、或做不滿 5 次，就記為 0（無法完成），並寫明原因。
- 椅子 43–45 cm、有靠背、獨立放置；其他高度要記錄；追蹤時要用同一高度的椅子。
- 起始時背靠椅背，每次之間盡量不碰椅背，也不要用腿後側抵住椅子。
- PDF 沒有任何角度、高度、幀數或追蹤相關的數字。**150°、0.7 個小腿長、連續 3 幀等程式數值，全部沒有依據，仍是待驗證的工程候選值。**

### 程式與 PDF 不一致

1. **用手推撐或別人協助**：PDF 要記為 0 或「無法完成」，第 1 次就要用手時應中止測試。程式偵測不到這些情況，仍會給出完成時間。這是最大的落差。
2. **坐回**：PDF 以「身體碰到椅子」為準；程式看髖部是否回到起始高度附近，懸空也可能被算成坐回，停止時間可能偏早。
3. **椅背**：PDF 要求起始時靠椅背、每次之間不碰椅背；App 的說明完全沒提。而且坐姿基準是在起始時建立的，之後每次坐下的位置可能不同，影響「坐回」的判斷。
4. **椅子與偏離紀錄**：PDF 要求記錄椅高，並在追蹤時使用同一張椅子；App 不記錄椅高，也沒有記錄任何偏離。
5. **計時開始**：從手機發出語音的那一刻起算，加上 3-2-1 倒數；PDF 只有「Go」。語音延遲沒有量過。
6. **「無法完成」沒有對應的狀態**：PDF 的「0／unable」是受測者依標準程序做不到。
   - 程式的「量測無效」是系統沒有量到，不是做不到。
   - 程式的「未完成」原因不明。
   - 用了手或有人協助，程式反而判為「完成」。
   - 三者都不能等同 PDF 的「無法完成」。（2026-10-21 更正：上一版寫成「方向相同、表示方式不同」）
7. **60 秒上限、偷跑重來、拒絕後多做一次補足**：PDF 都沒有寫，全部是程式自訂的做法。

### Excel 與 PDF 不同的地方（並列，不判定誰對）

- 椅高範圍：41–45 cm vs. 43–45 cm。
- 「無扶手」：PDF 沒寫。
- 「雙腳與肩同寬」：PDF 寫的是自選。
- 「預備、開始」：PDF 只有「Go」。
- 「臀部碰椅面」：PDF 寫「身體碰椅子」。
- Excel 沒有收錄「每次之間不碰椅背」「不要用腿後側抵住椅子」。

Excel 引用的是 SRALab 的另一個網頁和 Medbridge，這些原文都還沒核實。

### 仍需專業確認
