## 3. 解除關聯之後：新的讀取，以及已經載入的資料

| 範圍 | 處理方式 | 狀態 |
|---|---|---|
| 雲端**新的讀取**（五次坐站紀錄） | 規則每次讀取都會重新讀取關聯文件，狀態不是「已接受」就拒絕（R-S3） | **待驗證**（模擬器 R-S3、AR5；線上規則部署後再驗證一次） |
| 已載入到**復健師裝置**的副本 | 存在瀏覽器的 `localStorage`（集合清單）。規則**無法收回**已經送到裝置上的資料，App 也**沒有**在關聯結束時清除本機副本的機制 | 已知界線（讀程式確認） |
| 已開啟的頁面 | 沒有即時監聽，關聯結束之後，畫面上的資料會一直留到下次載入雲端資料（登入）為止 | 已知界線 |
| 復健師下次登入 | 五次坐站紀錄屬於**必要**集合，會被雲端查詢結果**整份取代**（`storageService.js` 的 `hydrateCloudForUser`，`writeRaw` 取代）。已結束關聯的紀錄不在查詢結果中，所以會從本機清單中移除 | 讀程式推論，**待驗證** |
| 登出 | 只清除記憶體中的雲端使用者（`app.js:1502`、`storageService.js` 的 `clearCloudUser`），**不清除 `localStorage`**。下一位使用者登入、資料被取代之前，副本都還留在裝置上 | 既有行為，不是 A 批造成的 |
| 選用集合（`trackingCycles` 等） | 登入時是本機與雲端**合併**，不是取代（`mergeById([local, cloud])`），所以前病人的週期副本，下次登入後**可能仍留在本機** | 既有行為，不在 A 批範圍 |
| 其他仍開放的集合 | `schedules`、`analysisRecords`、`patientAssessments` 對所有登入者開放；`recommendationResults` 的讀取也對所有登入者開放。這些集合**不受**關聯是否結束影響 | 既有規則，不在 A 批範圍 |
| Firestore 離線快取、Service Worker | 程式中都**沒有**啟用（`js/data/firebase.js` 只呼叫 `getFirestore`；全文找不到 `serviceWorker`） | 讀程式確認 |

**界線**
- A 批最多只能讓**之後新發出的**雲端讀取依關聯狀態判斷（待驗證）。
- 它**不會**刪除已經在裝置上的資料。
- 它**不涵蓋**其他集合。

## 4. 部署相容檢查：新 App、新規則與仍開著的舊版頁面

各階段的定義：

| 階段 | App | 規則 |
|---|---|---|
| P0 | 舊 | 舊（現況） |
| P1 | 新 | 舊 |
| P2 | 新 | 新（目標） |

「舊版頁面」指部署之後，使用者瀏覽器中**還沒重新整理**的分頁。程式沒有 Service Worker，重新整理後應該會載入新版，但取決於主機的快取設定，**待驗證**。

| 案例 | 階段與頁面 | 操作 | 預期 | 風險與處理 |
|---|---|---|---|---|
| D-1 | P1，新 App | 病人建立、完成評估、回報條件、登入時重新標記 | 全部成功 | 舊規則下沒有任何保護，不能宣稱已保護 |
| D-2 | P1，新 App | 復健師用三條件查詢登入 | 成功 | 標記之前的紀錄讀不到，要等病人用新 App 登入 |
| D-3 | P2，**舊版**復健師頁面 | 重新登入，或任何觸發載入雲端資料的動作 | 單一條件查詢被拒，登入失敗，顯示「無法載入雲端資料」 | 部署規則前要確認所有復健師都已載入新版；或接受「重新整理後就恢復」 |
| D-4 | P2，**舊版**病人頁面 | 建立或完成評估 | 成功（舊版不寫標記，規則把缺少的標記當成空值） | 這些紀錄要等病人用新 App 登入、重新標記後，復健師才讀得到 |
| D-5 | P2，**舊版**病人頁面 | 用過期的本機副本整份寫回一份「新 App 已追加回報」的紀錄 | 被拒（回報變少，不符合只能追加） | 舊頁面的寫入會**默默失敗**（只在主控台記錄），本機與雲端不一致。發生機率低：紀錄完成後，舊版沒有其他寫入路徑 |
| D-6 | P2，**舊版**病人頁面 | 舊版沒有寫入 `result` 之後再修改它的流程 | 不適用 | 讀程式確認 |
| D-7 | P2，新 App | AR1～AR15、R-S1～R-S11 | 符合預期 | 模擬器，待執行 |
| D-8 | P2 之後**回退 App** | 復健師登入 | 失敗（同 D-3） | 回退時要一起回退規則 |
| D-9 | P2 之後**回退規則** | 所有操作 | 恢復成完全開放 | 資料不受影響，但保護也一起消失 |
| D-10 | 部署規則**之前** | 確認線上實際的規則內容 | 已知、可比對 | 「推定已部署」的規則與專案中的規則檔不同（設計待辦 T8） |

**部署順序**（同 CHANGELIST 第 6 節）：P0 → P1 → 確認舊版復健師頁面都已更新（D-3）→ P2。
